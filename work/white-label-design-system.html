One design system, any brand

Role Solo designer and system ownerWorked with the development teamFor a global consulting firm
The short version

The firm wanted to launch branded websites for different clients without designing and building each one from scratch. Before designing anything, I set one rule: a new website should only need new settings, never new components. Then I built a system with nine switches, from brand and colour mode to language direction and density. A Figma AI agent did the production work. The architecture and every decision were mine.

The rule

A new website is created by changing:

ContentBrandThemeTypographyColour modeLanguage

…without changing:

ComponentsTemplatesLayout logicResponsivenessAccessibility structure

Everything else followed from that. If a decision would force someone to edit a component to launch a new brand, it was the wrong decision.

Two early scope calls kept it focused: responsive web only (no native apps), and a React front end, so the system's structure matches how developers would build it.

Five layers, from a colour value to a finished site

  1. Foundation tokens: raw colours, sizes, radii, shadows and fonts.
  2. Component tokens: what each component uses, pointing to roles, never raw values.
  3. React components, built by developers from the same token names.
  4. Templates and pages: home, services, blog, contact, search, 404.
  5. Branded sites: a brand is a set of switches, not a copy of the library.

The decisions that mattered

QuestionWhat I didn't doWhat I did
ArabicMake a mirrored copy of every componentMade language a switch: it flips direction, fonts and alignment in one go
BrandsCopy the library per brand and recolour itMade brand a switch on one shared library
ColoursLet components use raw colour valuesThree tiers: raw, then meaning, then component
Screen sizesSeparate desktop and mobile componentsBreakpoint tokens on the same components

Nine switches

Each one is a set of Figma variables with its own options. Pick one option per switch and you have a complete theme.

Redrawn with made-up brands, using the same token logic. The real brands are confidential.

The library ended up with 25+ components, 12 content blocks (hero, call to action, card grid, FAQ, gallery, forms, cookie consent, search) and 9 page templates, plus guides for designers and developers, a token guide, a CSS export workflow and a brand setup guide.

Working with an AI agent

I built this alone, so I used a Figma AI agent for the production work. It was fast at the repetitive parts: creating variables and options, and building component variants. It couldn't decide how the system should be structured, what to name things, or which trade-off to make. Those were mine, and I reviewed everything it produced.

That's the honest split. AI speeds up production. It doesn't replace judgement.

How I tested it

  • Every component has test frames in light, dark and high contrast, and in Arabic and English side by side.
  • I added five extra colour brands without touching a single component.
  • I rebuilt an existing client landing page from the system, to prove the rule worked on a real page and not just in documentation.
  • I agreed token names and the CSS file structure with the development team.

What happened

I handed the system and its documentation to an implementation partner to build the web components. I moved on before the build, so I don't have adoption numbers to show you.

Next time, I'd agree on a measurable target with the developers at the start, like how long it takes to launch a new brand, so the impact can be shown later.
